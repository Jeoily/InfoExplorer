# 单实例研究执行控制 v1

2026-10-25。Java 是任务状态的权威，Python 只执行检索与模型步骤。沿用创建 202、后台串行领取、失败执行编号重试及每任务最多五次。未引入分布式队列、租约或自动供应商重试。

## 用户接口

- `GET /api/v1/research-tasks/{id}/progress` 返回当前 `runId`、`stage`、`cancelRequested`、`reused` 和 `updatedAt`。阶段为 queued / starting / plan / search / read / review / report / verify / finished。它表示最近观察到的阶段，不是百分比或实时推送；短阶段可能在轮询间完成。
- `POST /api/v1/research-tasks/{id}/cancel`，请求 `{"expectedRunId":"当前执行 UUID"}`。排队尚无执行时传 null。旧执行编号不能取消新的执行，冲突返回 409。排队取消直接形成终态执行，不调用 Python；运行中先持久化取消意图，返回 202，等待当前请求结束后终止。
- 兼容现有状态枚举，取消最终保存为 `FAILED / EXECUTION_CANCELLED`。详情及历史显示“已取消”；列表的失败筛选仍包含取消任务。成功已提交的任务不被取消覆盖。
- `POST /{id}/retry` 仍使用 `failedRunId`，取消和中断终态均可手动重试。旧编号的重复重试不会重跑后一次失败。不自动重新调用模型。

React 每 1.5 秒读取运行中阶段、每 5 秒读取任务终态；刷新后从 Java 读取。新建提交在发请求前把问题、选项和幂等键保存在当前标签页 sessionStorage，确认响应后清除。响应丢失时刷新并保持相同输入再次提交会查回原任务；改动输入代表新任务。清除浏览器存储或换标签页不承诺保持该键。

## 跨服务控制与取消

Java 网络等待期间定期读取 Python 执行状态并保存到数据库，发现持久化取消意图则向 `/internal/research/executions/{runId}/cancel` 发取消指令。Python 使用取消标记及阶段边界检查，观察到取消后不再发送后续搜索、读取和模型步骤。已发出的请求不能保证撤销或停止计费，取消等待通常受当前阶段超时限制；模型阶段最多 45 秒，总研究预算 150 秒，Java 等待 175 秒并尝试取消上游。不是立即强杀模型供应商请求。

v2/v3 请求可选 `resumeFrom`。旧 v1 Wikipedia 使用可选 `X-Research-Run-Id` 请求头接入控制，历史无头调用保持原行为；Wikipedia 不复用搜索缓存。网页和 Wikipedia 控制接口仍只用于本机可信进程，未新增公网鉴权。

## 中断与安全复用

新增 H2 V11 / MySQL V9 表 `research_execution_control` 保存阶段、取消意图和复用计数。Java 启动先向遗留执行发送取消，再标记中断；已请求取消的遗留任务保留取消原因。PENDING 继续排队，完成结果不变。单线程 worker 持久化异常后，下次数据库可用时先执行同样恢复，再领取新任务，避免遗留 RUNNING 永久挂起。

Python 在本机 `INFOEXPLORER_EXECUTION_DIR` 下用 SQLite 保存执行身份、终态响应及成功取得的公开检索结果/正文。日常默认 agent-service/data/executions，隔离环境使用该隔离会话 executions，均在 E 盘工程下。不保存密钥或未校验的模型原文。启动时把遗留 RUNNING 标为 INTERRUPTED；相同编号只允许返回已保存终态，不自动重放运行中、异常或中断请求。

重试由 Java 传同任务上一失败执行编号。Python 核对问题、语言和模式哈希，按相同检索词或完整候选参数复用一小时内的成功结果；缓存缺失、过期或参数变化时正常检索。复用保留原获取时间，不刷新缓存年龄。当前复用仅限搜索/正文，模型规划、审核和报告重新执行；不是任意阶段断点续跑，也不是模型部分输出续写。预算中的搜索/文档数量仍是逻辑步骤数，`reused` 单独显示免网络复用数量。

完整响应保存解决同执行编号重发问题；Python 取得供应商结果但尚未保存终态时进程崩溃，仍无法证明供应商是否已处理请求。此情况需新的手动尝试，不声称跨进程 exactly-once。

执行控制库、缓存与调试记录是本机运行数据，不提交或上传；当前无自动历史清理。修改源码和选段算法后仍可复用原始公开正文，模型输出不会通过该缓存绕过当前验证。

## 验收

`scripts/check_reliability.py` 独立使用 18100 / 18180 / 15174、自有 H2 和固定外部工具样例，验证排队/运行取消、相同执行重复请求、Java/Python 进程中断、资料复用、截止时间、浏览器刷新及响应丢失后的提交恢复。退出时只结束它自己启动的进程。真实 HTTP 和数据库交互，不调用真实供应商，不能称为模型质量验收。MySQL 新迁移需另行运行显式临时库测试，日常库升级仍要求备份。
