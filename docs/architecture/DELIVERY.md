# 工程交付、可靠性与验证设计

日期：2026-10-15。基于当前代码审阅，区分已存在行为、发现的限制与后续设计。本轮不升级日常数据库、不停止用户服务、不执行 Git 操作。

## 1. 当前服务边界

浏览器 → Java API → Python 研究服务 → 搜索/模型；Java → MySQL 或 H2。Python 不直接写业务数据库，浏览器不直接持有模型或搜索凭据。

当前 Java 是单实例、单任务后台执行。数据库条件更新防止同一领取竞争产生重复 run，但启动恢复会把所有 RUNNING 标失败，故不能据此宣称可多实例运行。网络调用已在数据库事务外，这是应保留的边界。

当前生产式部署尚未实现。React 是 Vite 开发/预览入口，Java static 是旧原生页面；预览 CSP 的样式 nonce 没有移植到 Java。不要直接复制 dist 覆盖 static 后宣称已部署。

## 2. 本轮静态审阅发现（不是线上故障复现）

| 优先级 | 代码依据 | 限制/影响 | 后续处理 |
|---|---|---|---|

| 高 | ResearchRepository.recoverInterrupted 批量更新全部 RUNNING | 多实例启动会干扰另一实例任务 | 明确单实例部署门槛；多实例前加 owner/lease/fencing 与分布式恢复 |
| 中 | AgentClient 在反序列化后验证字符串和证据长度 | 验证发生在接收和解析之后，尚无明确 HTTP 成功响应字节总上限 | 使用有界响应读取，再解析/校验；错误响应也避免先无限读取 |

这些是代码路径分析，尚未通过真实数据库断网或进程崩溃实验逐一复现。不得用“已修复”描述本轮仅设计的条目。

## 3. 任务完成与持久化失败

必须区分三类失败：研究本身失败、结果保存失败、客户端没收到回复。客户端查询失败不能触发自动重新研究。

近期方案：Java 保存执行终态采用独立短事务，对可明确判断为瞬时连接问题的保存失败进行有限重试，只重试保存，不重调 Python。每次持久化带 runId，终态写入保持幂等，防止第一次事务已提交但响应丢失产生重复证据。重试次数与间隔有上限，不能阻塞整个应用无限等待。

限制：进程在收到报告后、写库前崩溃，内存结果仍会丢失。需要跨崩溃保存时再设计本机加密结果暂存或独立持久化队列，不把内存重试称为持久保证。不得为此把带业务内容的报告写入普通日志。

未来多实例必须：lease_until、owner_id、fencing_version、定期心跳、到期回收、完成时核对 fencing_version。外部模型调用不可能仅靠数据库事务保证 exactly-once；必须承认网络不确定性并记录调用尝试，避免自动重复付费请求。

## 4. 数据库设计与迁移规范

- 延续 Java 统一事务保存任务、run、source、evidence。需要查询/约束的关系用关系表，阶段详情和供应商诊断用受限 JSON；不要把整个数据库做成一列 JSON。
- 保留版本化迁移，已应用的 H2/MySQL 旧迁移不改。新增字段先兼容旧数据，再切换新接口；不能给旧记录编造来源或事件时间。
- 新字段在 Java/Python/前端明确最大长度、可空性、枚举；跨语言字符串预算使用 UTF-16 单元，哈希使用精确定义的 UTF-8 文本。
- 任务列表当前 OFFSET 适合小数据。历史和事件流增长后使用 createdAt+id 游标；索引按真实 WHERE/ORDER BY 设计，并用 EXPLAIN 验证，不凭空声称优化提升。
- research_run(task_id,attempt_no)、tracking_cycle(topic_id,slot_key) 以唯一约束兜底，前端按钮禁用不能替代数据库约束。
- 幂等键未来按用户/操作范围隔离。不能给所有用户共用当前全局 key 空间。

日常库迁移顺序：停止访问库的 Java → 导出备份并记录校验 → 隔离库验证升级 → 启动日常库迁移 → 检查旧记录与新链路。导出成功不等于恢复已验证。MySQL DDL 可能部分提交，失败时先诊断，不自动 flyway repair 或覆盖恢复。

## 5. 搜索与正文边界

SearXNG 是受信的固定连接目标；正文 URL 是外部输入，两者必须用不同策略。检索返回 localhost、内网、凭据 URL、特殊端口时拒绝。DNS 校验后必须把实际连接固定到已检查的 IP，否则字符串校验无法阻止 DNS 重绑定。每次跳转重新检查，TLS 仍按原主机名验证。

下载器应限制：连接/总时限、跳转数、压缩前后字节、媒体类型、每域并发、robots 处理、解析器时间和内存。禁止读取本机 cookie/浏览器资料，不执行网页脚本，禁用自动继承系统代理。Crawl4AI 只有在隔离进程和所有子资源请求也能受控后加入。

url_policy 本身只是离线地址策略；2026-10-15 新增独立 download.py 已绑定已核验 IP、核对 TLS 和逐跳目标，并对保守 robots 与有界正文做测试，尚未接入业务。预算类只是计数和 deadline 检查，不自动取消请求。下载器仅单个真实公开页面验证，不支持压缩/复杂 robots/JS，没有跨进程限流或 OS 内存沙箱。不要因为单元测试通过就放开任意 URL 网络访问。

参考：[OWASP SSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

## 6. 身份与部署选择

近期演示目标保持 localhost，无需先做注册系统。外部演示可通过录屏/本机演示完成，不把开发服务直接绑定 0.0.0.0。

如果后续要公网多人使用：优先采用 Spring Security 的标准会话或受支持身份提供方；选择后统一 cookie、CSRF、退出、权限与前端错误处理。不要自行拼装密码加密和 JWT 刷新协议。所有 task/run/topic/event 查询按主体检查归属，子资源路由同样检查；同时限制任务队列、模型预算和请求速率。

部署先考虑一个 Java 实例、一个 Python 实例、MySQL 和自建 SearXNG；React 静态资源由同源网关或经验证的 Java 入口提供。仅暴露 Web 入口，数据库和 Python/SearXNG 不公开。健康检查不通过调用付费模型来探活。

正式构建采用可重复的锁定版本、配置模板和容器/运行说明；具体镜像在实现时核验并固定版本，不使用无约束 latest。当前 Windows 未发现 docker 命令，WSL 状态检查返回未安装信息；本轮未安装系统组件，部署仍未验证。

## 7. 可观测性与成本

每个请求/任务/执行带独立关联 ID，日志只记录阶段、耗时、计数、安全错误码和配置版本，不记原始密码、Authorization、用户问题或完整网页正文。必要诊断信息保存在受控业务记录，不泄露到公开错误响应。

建议指标：排队时长、阶段耗时、任务终态、空结果比例、下载成功率、预算耗尽次数、模型响应拒绝原因、持久化失败数、主题调度跳过次数。来源数量和词匹配分数不作为准确率。

搜索与正文自部署仍消耗 CPU/内存/网络；模型 usage 可能缺失。记录调用次数和可得 usage，费用只引用实际账单/明确计价，不自动把免费优惠当永久承诺。

## 8. 验证层次

| 层次 | 依赖 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 纯函数/模块测试 | 本机 Python，无网络 | 地址策略、预算、解析、去重、引用映射 | 引擎可达、真实网页提取质量 |
| 离线 HTTP 契约 | 本机随机端口 + 模拟上游 | Java/Python 字段与错误契约 | 真实模型兼容性 |
| H2 集成 | 临时内存/文件库 | 事务和迁移逻辑、历史兼容 | MySQL 行为完全相同 |
| MySQL opt-in | 用户交互凭据、随机临时库 | 真约束、迁移、事务和并发 | 日常库已升级 |
| 浏览器离线联调 | 隔离 Java/H2/模拟 Agent | 创建、读取、失败、引用、刷新、响应式 | 真实搜索覆盖 |
| 公开资料真实联调 | 明确来源、模型/预算 | 一条真实执行路径可用 | 所有问题效果、长期稳定性 |

普通测试不外联。安全测试用本机夹具模拟恶意跳转/DNS/超大响应，不访问内网目标。用户不希望建立固定问题评测集，故只做必要功能和可靠性测试，质量结论保持克制。

## 9. 交付清单与演示

一次可展示交付应包含：启动说明、已知限制、一条可追溯研究记录、一条失败降级示例、一条跨轮资料变化示例、测试摘要和架构图。示例数据明确标注，不能用离线夹具冒充真实结果。

GitHub 初始化、仓库创建、提交、上传仍需用户另行授权。上传前排除 .venv、node_modules、target、dist、日志、备份、数据库、凭据和私人业务数据；Private 仓库同样不能保存秘密。依赖许可证与来源归属在正式打包前核对。

## 10. 可恢复的前端阶段事件草案

2026-10-15 开源源码调研补充，尚未实现。采用“事实事件”而不是模型思维全文：queued、planning、search_started/completed、source_read_started/completed、coverage_reviewed、report_started/completed、persisted、failed。每项说明执行了什么、耗时与结果，不保存隐藏推理或原始网页指令。

- Java 分配 runId，持久化事件使用 (runId, sequence) 唯一键；sequence 单调递增，不使用浏览器时间作为顺序。
- 每条记录包含 schemaVersion、runId、sequence、eventType、occurredAt、phase、safeCode、queryId/sourceId（可空）和有长度上限的摘要。计数是实际尝试数，不把搜索结果数量当成本。
- Python 的内部阶段序号与 Java 持久化序号分开；重复接收同一 producerEventId 幂等，不重复插入。阶段传输方式须另行实现，当前同步终态接口不能提前声称支持实时进度。
- 首版可先轮询事件游标，GET 候选接口 /api/v2/research-runs/{runId}/events?after=sequence&limit=50。SSE 只是后续传输选择，不代替落库。前端刷新从游标续读，先去重再追加；断线不触发任务重跑。
- 最终结果按 runId 独立读取。浏览器看到 report_completed 不代表事务已经提交；只有 persisted 或终态查询确认后显示“已保存”。失败时仍可读取已经持久化的证据。
- 查询失败、暂时没有新事件、执行失败和事件保留期已过要区分。历史事件被清理后，前端重新加载执行摘要，不无限重连同一个不可用游标。

实施需跨 Java/Python/React 契约、数据库迁移和断线恢复测试，不能只加一个前端动画。参考 Vane 的 responseBlocks/AssistantSteps 和 Morphic 的 searching/complete 输出，具体代码链接见开源调研报告。
