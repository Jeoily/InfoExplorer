## 2026-10-15：后续网页研究与事件追踪（尚未接入）

现有页面继续服务 Wikipedia 版本。后续页面和实际 API 同批实现，不先改成“全网搜索”掩盖底层尚未升级。

研究详情采用三个视图：**回答**显示结论、覆盖程度、缺口与引用；**证据**显示来源、段落、发布时间/获取时间、读取方式与截断提示；**研究过程**显示实际查询、初次/补充轮次、读取失败、预算和停止原因。没有实时阶段 API 时不展示虚构的进度。

| 后端语义 | 用户文案 | 操作 |
|---|---|---|
| PENDING/RUNNING | 已排队/正在研究 | 查询状态，不重复创建 |
| SUCCEEDED + sufficient | 研究完成，资料覆盖了计划问题 | 阅读依据；覆盖是模型判断，不是事实认证 |
| SUCCEEDED + partial | 本轮完成，部分问题缺少资料 | 查看缺口、调整范围创建新任务 |
| SUCCEEDED + unknown | 已取得资料，未评估覆盖程度 | 阅读摘录与来源 |
| 零可用正文 | 未获得可用正文 | 查看搜索/读取原因，不说“没有相关事实” |
| FAILED + 有证据 | 执行未完成，已保留部分资料 | 阅读证据、查看失败阶段、按现有规则重试 |
| FAILED + 无证据 | 本次研究失败 | 解释安全错误码，不展示伪造的空报告 |

历史执行页打开对应 run 的报告，不总展示最新结果。引用 DOM ID 使用 runId + evidenceId，避免同屏比较时 E1 冲突；点击引用移焦到证据并可返回阅读位置。搜索摘要只作为候选资料，不能混入正文证据卡。

追踪入口等后端可用后再开放：主题列表、主题时间线、轮次对比。创建默认手动检查；定时设置说明频率、模型状态和预算。暂停文案明确“停止新轮次，正在执行的轮次继续完成”；归档保留历史。发生时间未知时按发现时间排列并标注，修订显示旧版本和对应证据，冲突说法并列展示。

TanStack Query 的 query key 包含任务/执行/主题 ID 与筛选；完成后停止轮询，隐藏标签暂停。读请求失败与写请求超时使用不同文案：只有写请求才提示“可能已受理”。保留纯文本渲染，未来 Markdown 需单独清理与链接策略。先轮询真实阶段数据，确需低延迟再引入 SSE。

## 目标与边界

让用户完成“输入公开主题 → 查看执行状态 → 阅读报告 → 核对证据 → 必要时手动重试”的完整流程。第一版重点是可解释的任务状态和可核对的来源，不增加后端尚不支持的功能。现有搜索只有 Wikipedia，输入框说明使用主题关键词；不宣称全网搜索、新闻实时监测或复杂问题自动规划。

Java 仍管理业务接口和数据库，Python 仍负责检索及可选模型报告。浏览器不直连 MySQL、Python 或模型供应商，不配置数据库密码或模型密钥。Node.js 用于开发与构建，不新增 Node 业务后端。

## 页面与操作流程

第一版桌面布局采用左侧导航与主内容区，窄屏导航转为顶部。统一空状态、加载、失败、重试和键盘焦点样式。视觉以清晰的报告阅读为主，保留现有绿色强调色作为初始方向，可在正式实现时调整。

| 页面 | 路由设计 | 用户操作与内容 | 数据支持 |
|---|---|---|---|
| 开始研究 | /research/new | 输入主题、查看搜索范围和公开数据提示、提交；成功跳到任务详情 | 现有创建接口 |
| 研究任务 | /tasks?page=0&status=FAILED | 每页 10 项、四种状态筛选、进入详情；过滤条件保存在 URL，可返回原列表 | 现有分页接口，无总数 |
| 报告详情 | /tasks/:id | 主题与真实任务状态、报告、证据、执行历史、失败重试 | 现有详情/历史/重试接口 |

```text
桌面报告页
┌────────────┬──────────────────────────────────────────┐
│ InfoExplorer│ 主题                 状态 / 更新时间     │
│ 开始研究    │ 状态说明、失败原因与允许的操作             │
│ 研究任务    ├────────────────────────┬─────────────────┤
│            │ 报告正文               │ 证据列表         │
│            │ 引用 [E1] → 定位证据   │ 标题、摘录、链接 │
│            ├────────────────────────┴─────────────────┤
│            │ 执行历史：次数、开始/结束时间、错误原因     │
└────────────┴──────────────────────────────────────────┘
窄屏：主题 → 状态 → 报告 → 证据 → 执行历史，单列排列。
```

详情按状态展示：PENDING 仅说明等待；RUNNING 仅说明处理中，不伪造百分比或模型思考过程；SUCCEEDED 展示已有结果，区分资料摘录与模型报告；FAILED 显示安全错误说明、执行历史及允许的重试操作。查询失败与任务执行失败必须使用不同文案。

报告引用只对已存在的证据 ID 提供页面内定位，不把任意文本转换为 HTML。证据获取时间不标为事件发生时间，哈希不标为真实性认证。没有证据时显示实际无结果状态，不伪造来源。首版保持纯文本报告，暂不引入 Markdown 渲染。

## 技术选择与工程边界

选用 React、TypeScript、Vite、React Router、TanStack Query、Ant Design。测试采用 Vitest、React Testing Library 和 Playwright，规范工具采用 ESLint、Prettier。具体版本在搭建时核对依赖兼容性并写入锁文件；本设计不指定未经验证的版本。

- React 组件管理页面结构；TypeScript 定义任务状态、概要、详情、证据与错误结构。
- URL 保存页码、状态筛选和当前任务标识。TanStack Query 管理接口数据；组件本地状态管理表单与弹窗。首版不引入 Redux/Zustand。
- 查询键包含所有查询参数和任务 ID，利用取消信号避免过期请求浪费；不能显示另一任务的缓存详情作为当前任务。默认不自动重试创建或执行重试等写请求。GET 是否有限重试须显式配置。
- 活跃任务初始按 5 秒轮询，终态详情停止轮询，隐藏标签暂停；保留手动刷新。列表按需刷新，创建/重试成功后使相关缓存失效。暂不增加 SSE/WebSocket。
- 同页网络错误后的相同创建请求复用幂等键；不自动反复提交。当前阶段不承诺跨刷新恢复提交键。重试绑定 failedRunId，前端按钮防重复，后端事务作最终仲裁。
- Ant Design 用于表单、按钮、分页与确认框，报告及证据组件独立设计。默认组件库样式不能替代产品信息布局。

工程目录为 E:\InfoExplorer\frontend。src/main.tsx 管理路由与 providers，src/api 管理请求与契约类型，src/features/research 为三个业务页面，src/components 为状态与报告组件，src/styles.css 为样式，tests 为浏览器测试。页面按路由懒加载，不引入不必要的空目录。

开发时 Vite 只监听本机，/api 代理到本机 Java，避免为开发放宽后端跨域规则。正式构建产物的发布方式需在迁移时验证；候选方案为 Java 同源提供构建资源，路由可采用 hash 模式避免刷新回退问题，或显式实现仅页面路由的回退规则。不能把 API 错误回退成 index.html。现有原生页面在新页面验收前保留，不自动复制覆盖。

必须验证现有 BrowserSecurityFilter 的 CSP 与 Ant Design 运行时样式兼容。优先评估 nonce 或可行的静态样式方案；不得为使界面显示而直接放宽全部脚本权限。若改变安全头，需增加对应 Java 测试。

## 验收标准与实施顺序

1. 创建独立前端工程，安装依赖并生成锁文件，验证类型检查、代码规范和生产构建；不覆盖原页面、不启用日常数据库迁移。
2. 实现三类页面及现有接口适配，测试空列表、过滤翻页、无效任务 ID、查询失败、报告引用与键盘操作。
3. 覆盖响应丢失后的创建去重、快速切换详情、失败执行版本变化、达到 5 次执行上限，以及重复点击重试。
4. 使用真实 Java HTTP、隔离 H2 和模拟 Agent 做浏览器联调，验证桌面/窄屏、长文本、恶意 HTML 文本、证据链接、安全头与历史保留；不称为真实模型测试。
5. 再决定替换旧入口与部署方式。日常 MySQL 升级和真实模型验证是独立步骤，需要本机凭据及相应准备。

当前环境：Node.js v24.17.0、npm 11.13.0，前端依赖已安装并使用 package-lock.json 固定。采用 React 19.3.0、Vite 8.3.4、Ant Design 6.6.6，完整版本见 package.json。无需用户额外下载桌面软件，未初始化 Git。
