# 研究阶段记录与离线回放

2026-10-25 第二阶段。保留阶段输入和输出，让选段、报告逻辑能够独立调试。范围是隔离调试环境；不修改日常数据库、HTTP 契约或页面，不是断点续跑或实时进度功能。

## 记录内容

默认固定样例自动记录在 `E:\InfoExplorer\logs\debug\<管理会话>\recordings\<记录编号>`。

`manifest.json` 包含 runId、问题、语言、模式、代码文件摘要、事件索引和记录状态。编号 JSON 文件保存：

- 模型规划、审核、报告的请求，以及通过结构和业务校验的输出。
- 搜索查询与候选结果；正文读取的全部受限段落和元数据（不是原始 HTML）。
- 选段时的问题、正文集合、选出证据；会话终态快照。
- 失败阶段的固定错误类别、安全诊断原因及阶段耗时。

不保存 API Key、鉴权信息、供应商响应信封或未通过校验的模型原文。记录会包含问题和正文，不能自动清除误输入的私人信息，因此只使用公开示例，不上传运行目录。

真实模式默认不保存完整阶段资料。将来确认真实调用配置、计费及额度后，可给 `Start-Debug.ps1` 加 `-RecordPublic` 显式开启。此开关不授予调用额度，不改变计数和授权要求。本阶段未调用真实供应商。

## 不联网复查

### 在网页中查看（第三阶段）

启动隔离调试环境后，在 `http://127.0.0.1:15173` 创建“模型研究”任务。任务详情下方的“阶段复查”可以读取保存的记录，显示每阶段状态、耗时、正文/证据数量和失败原因。展开“阶段输入与输出”查看公开数据；输入内容只按文本展示，不执行 HTML。

三个按钮分别执行完整离线回放、重新选择证据和检查已保存报告。均不搜索、不调用真实模型、不改原任务。回放完成但研究失败会明确显示“复现了原研究的失败”。没有记录、记录损坏或输入与当前代码不匹配时显示提示，不自动重试。刷新及历史执行弹窗按各自 runId 读取记录；不自动轮询，不显示成实时进度。

这些入口仅在隔离管理器启动的前端启用，代理固定指向本机 18000 的 debug_agent。日常 Python 不导入此接口，日常前端默认隐藏。浏览器不接受本机文件路径；只按 UUID 查找当前管理会话的记录，不暴露提示指令或原始供应商响应。它仍是本机开发诊断，不适用于公网开放或多用户授权。

默认样例：`Public topic` 成功、`fail report` 报告失败、`supplement` 补搜、`empty` 无资料。不要用这些样例结果评价真实回答质量。旧管理会话的记录仍可通过下述 CLI 查阅，页面只查当前管理会话。

### 命令行

在项目目录 PowerShell 中，把记录路径替换为实际目录：

```powershell
$record = 'E:\InfoExplorer\logs\debug\<管理会话>\recordings\<记录编号>'
& .\backend\agent-service\.venv\Scripts\python.exe scripts/replay_research.py inspect $record
```

将 `inspect` 替换为以下操作：

| 操作 | 用途 |
| --- | --- |
| inspect | 阶段成功、失败、耗时及中断位置 |
| session | 使用保存的工具结果重跑当前协调逻辑 |
| select | 当前算法重新筛选保存正文，列出新增/移除段落 |
| report-input | 导出报告阶段输入、证据和提示 |
| report-check | 当前校验逻辑复查已保存的合格报告并渲染 |

追加 `--output 'E:\InfoExplorer\logs\replay-result.json'` 可保存结果；目标文件必须不存在。命令不需要服务、数据库或密钥，不连接供应商和网页。回放结果中的模型调用计数是协调器的逻辑计数，外部请求为零。

完整回放严格匹配阶段输入和顺序。修改提示或选择结果导致输入变化时明确拒绝，不偷偷调用外网。此时使用 select 或固定证据生成。回放不重现原网络延迟，剩余时间不要求与原执行一致。

## 固定证据报告生成

开发函数 `app.web_research.recording.regenerate_report(record_path, complete)` 使用保存的最终报告数据、当前请求构造器和相同的报告校验器，只调用注入的 `complete(stage, request, timeout)` 一次。不会规划、搜索、读取正文或审核，也不改原记录和业务库。返回父记录编号、输入摘要、报告和答案。

本轮只用合成模型验证该入口，包括拒绝不在证据中的引用。离线 CLI 没有接入真实供应商。将来使用真实 completion 必须先确认配置、计费和额度，由调用方预约预算；此开发函数不能作为绕过预算的入口。新结果应另存，原记录不变。

## 限制与故障

- 单事件最大 1 MiB、总事件最大 16 MiB、最多 80 个。通过临时文件替换写入并校验 SHA-256；摘要用于检查意外损坏，不是防篡改签名。
- COMPLETE 表示记录正常结束，研究是否成功另看 researchStatus。RECORDING/INCOMPLETE 不能做完整回放，但可查看已落盘阶段。
- 初始化目录失败时研究尚未执行即失败。开始记录后的写盘故障不改变研究结果，也不能把不完整记录当作完整记录。
- 被拒绝的模型输出只保留失败类别；回放模拟失败，不能逐字重现原始错误文本。
- select 当前重跑最后一次选段；不是任意中间状态恢复。历史未记录任务无法补回正文，不自动搜索补齐。
- 记录保留在 E 盘，不自动清理；运行目录不应提交或上传。

## 验证

`tests/test_recording.py` 覆盖完整/补搜回放、模型及工具失败、输入变化拒绝、文件损坏、记录上限、写盘故障、中断、重新选段、固定证据生成和引用约束。

`scripts/check_debug_env.py` 验证真实本机 Java/Python/前端代理任务落盘、离线 CLI、重启后的记录与 H2 保留。搜索和模型仍是合成样例；日常 MySQL、真实供应商和真实回答质量不在本阶段验收范围。
